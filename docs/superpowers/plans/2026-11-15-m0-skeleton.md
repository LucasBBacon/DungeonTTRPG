# M0 Skeleton Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Godot-free C# rules core with a deterministic command and event loop, pending decisions, saves and replays, plus a Godot project that draws a placeholder 3D isometric grid and moves one unit through that core.

**Architecture:** `src/Core` is a class library holding an immutable `GameState` and a pure function `Engine.Apply(state, command)` that returns a new state plus a list of events. `game/` is a Godot project that references `Core`, turns clicks into commands and plays events as animation; it never changes game state itself. All randomness comes from seeded PCG32 streams stored in the state.

**Tech Stack:** C# on .NET 8, xUnit, System.Text.Json, System.Collections.Immutable, Godot 4 (.NET build), GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-15-dungeon-rpg-design.md`. This plan covers milestone M0 only. M1–M4 each get their own plan.

## Global Constraints

- `src/Core` has no Godot references. Any game rule in a Godot script defeats the architecture.
- The same seed and the same inputs always produce the same run.
- The core uses its own seeded random number generator, not `System.Random`.
- Separate random streams for dungeon generation, combat rolls and loot.
- Rules use integer arithmetic only. No `float` or `double` in `src/Core`.
- No reliance on unordered collection iteration in `src/Core`: no `Dictionary` or `HashSet` enumeration.
- Square grid, 8 directions, a diagonal step costs the same as an orthogonal step.
- The rules grid is flat: one level per floor, no height.
- While a decision is pending, the only valid command is an answer to it.
- Saves carry a version number.
- Builds target Windows and Linux. Input is mouse and keyboard through remappable Godot input actions.
- Presentation is isometric 3D using placeholder meshes and flat materials.
- Root namespace is `Dungeon.Core`. Nullable reference types on, warnings as errors.
- Grid convention: `X` grows east, `Y` grows south, row 0 of a parsed map is `Y = 0`.

Plan-level calls not fixed by the spec:

- A diagonal step is rejected if either orthogonally adjacent square is a wall (no corner cutting).
- `Sim` (the balance simulator) is not created in M0; it has nothing to simulate until M1.
- Wall cut-away and fade are deferred to M1. M0 uses half-height walls so nothing is hidden.
- The Godot version is the builders' choice. If its .NET requirement is not 8, change `TargetFramework` everywhere in Task 1.

## Review Focus

1. A save file that is corrupt or written by a newer version: loading reports a typed error and never crashes or half-loads. (Task 6)
2. A click outside the map, on a wall, or on an unreachable square: nothing happens. (Task 7, Task 8)
3. Input arriving while a decision is pending or while animations are still playing: rejected or ignored, never applied out of order. (Task 5, Task 8)
4. A command naming a unit or decision that does not exist: rejected with an error code, state unchanged. (Task 4, Task 5)
5. A malformed map (empty, ragged rows, unknown character) or a non-positive random bound: throws an argument exception that names the problem. (Task 2, Task 3)

- [ ] **Step 3: Implement `Pcg32` and `RngStreams`**

The algorithm is fixed; all arithmetic is `unchecked`:

```csharp
// Seed
var s = new RngState(0, (stream << 1) | 1);
s = Step(s); s = s with { State = s.State + seed }; s = Step(s);
// Step
new RngState(s.State * 6364136223846793005UL + s.Inc, s.Inc)
// NextUInt: output is computed from the state BEFORE stepping
uint x = (uint)(((old >> 18) ^ old) >> 27); int rot = (int)(old >> 59);
uint value = (x >> rot) | (x << ((-rot) & 31));
// NextInt(bound): rejection sampling, no modulo bias
uint b = (uint)bound; uint threshold = (uint)(-b) % b;
// draw r until r >= threshold, return (int)(r % b)
```

If the reference test fails, the bug is in the implementation, not the expected values: they are the published output of the PCG32 reference demo for seed 42, stream 54.

### Task 5: Pending decisions

**Files:**
- Modify: `src/Core/Engine/Commands.cs`, `src/Core/Engine/Events.cs`, `src/Core/Engine/Engine.cs`
- Test: `tests/Core.Tests/DecisionTests.cs`

**Interfaces:**
- Consumes: everything from Task 4; `Pcg32.NextInt` from Task 2.
- Produces:
  - `sealed record AnswerDecisionCommand(DecisionId Decision, int OptionIndex) : Command`
  - `sealed record DecisionRequested(PendingDecision Decision) : GameEvent`
  - `sealed record DecisionResolved(DecisionId Decision, UnitId Unit, int ChosenOption) : GameEvent`
  - `sealed record TileChanged(GridPos Pos, Tile Tile) : GameEvent`
- Behaviour:
  - Moving onto a `Shrine` tile emits `UnitMoved`, `TickAdvanced`, then `DecisionRequested`, and sets `GameState.Pending`.
  - The decision offers 3 distinct boon ids from 0..9, drawn from the `Loot` stream by repeated `NextInt(10)`, skipping duplicates, in draw order. Only the `Loot` stream advances.
  - The decision id is `NextDecisionId`, which then increments.
  - Answering appends `Options[OptionIndex]` to the unit's `Boons`, turns the shrine at `Source` into `Floor`, clears `Pending`, and emits `DecisionResolved` then `TileChanged`. `Tick` does not change.

### Task 6: Snapshots, command log and replay

**Files:**
- Create: `src/Core/Persistence/Snapshot.cs`, `src/Core/Persistence/CommandLog.cs`
- Test: `tests/Core.Tests/PersistenceTests.cs`

**Interfaces:**
- Consumes: `GameState`, `Command` subtypes, `Engine.Apply`, `GridMap.Parse`, `GridMap.ToRows`.
- Produces:
  - `static class Snapshot`: `const int CurrentVersion = 1`, `string Save(GameState s)`, `GameState Load(string json)`
  - `sealed class SnapshotFormatException : Exception`; `sealed class SnapshotVersionException : Exception` with `int Found`
  - `sealed record CommandLog(ulong Seed, ImmutableArray<Command> Commands)` with `string Save()` and `static CommandLog Load(string json)`
  - `static class Replay`: `GameState Run(GameState initial, IEnumerable<Command> commands)`

- Format: single-line JSON, `"version"` as the first property, the map stored as its `ToRows()` strings, commands tagged with `"type": "move"` or `"type": "answer"`. `Save` output is canonical: two equal states produce identical strings. Tests compare states by comparing `Snapshot.Save` output.

### Task 8: Godot display layer

**Files:**
- Create: `game/project.godot`, `game/Game.csproj`, `game/Main.tscn`
- Create: `game/scripts/GameController.cs`, `BoardView.cs`, `UnitView.cs`, `IsoCamera.cs`, `GridCoords.cs`, `DecisionPanel.cs`, `DemoLevel.cs`

**Interfaces:**
- Consumes: `GameState.Create`, `Engine.Apply`, `StepResult`, all `GameEvent` subtypes, `Queries.FindPath`, `MoveCommand`, `AnswerDecisionCommand`, `GridMap`, `Tile`.
- Produces: nothing consumed by later M0 tasks. M1 builds on `GameController`'s event queue.

Decisions:

- `Game.csproj` has a `ProjectReference` to `../src/Core/Core.csproj`. It is not added to `Dungeon.sln`; Godot generates and owns `game/Game.sln`.
- One grid square is 1 world unit. `GridCoords.ToWorld(GridPos p)` returns `new Vector3(p.X + 0.5f, 0, p.Y + 0.5f)`. `GridCoords.FromWorld(Vector3 v)` floors `v.X` and `v.Z`. This is the only place screen or world positions become grid squares.
- `IsoCamera`: orthographic `Camera3D`, pitch 35.264 degrees below horizontal, yaw starting at 45 degrees, looking at the map centre. Rotates in 90 degree steps with a 0.2 second tween.
- Input actions, defined in `project.godot` so they are remappable: `select` (left mouse), `cam_rotate_left` (Q), `cam_rotate_right` (E), `option_1`, `option_2`, `option_3` (keys 1, 2, 3).
- `BoardView` builds the board from `GridMap` using primitive meshes with flat-colour materials: floor a thin grey box, wall a dark box 0.5 high, shrine a gold box 0.2 high. It rebuilds one square on `TileChanged`.
- `UnitView` is a capsule. On `UnitMoved` it tweens to the new square over 0.15 seconds.
- `DemoLevel` holds a fixed 12 by 8 map with a wall border, a few interior walls and two shrines, the hero start square, and seed `12345`.
- `GameController` owns the current `GameState`. On `select` it ray-casts from the camera to the plane `y = 0`, converts with `GridCoords.FromWorld`, calls `Queries.FindPath`, and for each direction applies a `MoveCommand`, appending the returned events to a queue. It stops applying a path as soon as a result is not `Ok` or a decision becomes pending. Events are played one at a time; each view signals when its animation ends.
- `GameController` ignores `select` while the event queue is non-empty or a decision is pending.
- `DecisionPanel` appears on `DecisionRequested` with one button per option, labelled `Boon <id>`, and hides on `DecisionResolved`. Buttons and `option_1..3` submit `AnswerDecisionCommand`.
- No game rule is evaluated in `game/`. Legality comes only from `Engine.Apply` and `Queries`.
