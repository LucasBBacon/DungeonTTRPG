# M1-02 Key Algebra Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace PCG32 with the SplitMix64 key algebra that every random draw in the game derives from, and move the M0 engine and saves onto it.

**Architecture:** One file, `src/Core/Random/KeyAlgebra.cs`, holds the pure key functions (`Mix`, `LabelId`, `Absorb`, `Derive`, `Draw`, `Bound`, `H`, `D20`) and the counter stream `DrawStream`, all wrapping arithmetic inside `unchecked { }`; it becomes the analyzer's one exempt file (`DungeonWrappingArithmeticFile`). Keyed sorts and the 60-bit run seed sit beside it in ordinary checked files. The M0 state keeps its `runSeed` plus two stream counters (`combat`, the M0 shrine stream); keys are re-derived from the seed, never saved. `Engine.DrawBoons` becomes a fixed three-draw partial Fisher–Yates.

**Tech Stack:** C# 12 / .NET 8, xUnit, `Math.BigMul` for `Bound`. Builds on M1-01 (branch `m1-01-build-guards`, PR #88): the determinism analyzer, `IntMath`, `[TotalComparer]`, checked arithmetic in Debug and CI.

**Spec:** [`docs/roadmap/m1-vertical-slice.md` — M1-02](../../roadmap/m1-vertical-slice.md#m1-02-key-algebra), implementing SV 4.1 (key algebra, K-rules 1–7, reference vectors), SV 4.2 (streams, path grammar), SV 4.3 (`combat` row, 60-bit root), SV-7, SV-8; MAIN 6.3. SV = `docs/superpowers/specs/2026-11-23-seeds-validation-design.md`.

## Global Constraints

- SV 4.1, verbatim: `γ = 0x9E3779B97F4A7C15`; `Mix(z)`: `z ^= z >> 30; z *= 0xBF58476D1CE4E5B9; z ^= z >> 27; z *= 0x94D049BB133111EB; z ^= z >> 31`; `LabelId(s)` = FNV-1a-64 over UTF-8 bytes, offset `0xcbf29ce484222325`, prime `0x100000001b3`; `Absorb(h, x) = Mix(h ^ Mix(x + γ))`; `Derive(k, label, i1..in)`: `h = Absorb(k, LabelId(label))`, then `h = Absorb(h, ij)` per index, return `Absorb(h, 0xD1B54A32D192ED03 ^ n)`; `Draw(k, i) = Mix(k + (i + 1)·γ)`; `Bound(u, n)` = high 64 bits of `u × n`, asserts `n ≥ 1` in every build; `H(k, domain, parts..) = Draw(Derive(k, domain, parts..), 0)`; `D20(u) = 1 + Bound(u, 20)`.
- All key arithmetic is unsigned 64-bit, modulo 2^64, inside explicit `unchecked { }` in the one key-algebra file. Every `Derive`/`H` index is `ulong` (or `uint` zero-extended), never signed.
- Path grammar (SV 4.2): each label plus the indices that follow it is **one** `Derive` call; a path's key is a left fold of `Derive` from `runSeed`; root children derive directly from `runSeed` (`dungeon = Derive(runSeed, "dungeon")`). A string index enters only as `LabelId(id)` (K-rule 2). Arity is part of the key.
- A stream is (key, counter); `Next()` returns `Draw(key, counter++)`; `Skip(n)` adds n; draw indices are 0-based (DS15).
- K-rule 7: a keyed sort orders by (H value, then ordinal comparison of the stable id).
- `runSeed` is a 60-bit integer; seeds ≥ 2^60 are rejected (SV 4.3, 4.9). No salt option anywhere (SV-7).
- `combat` is `Derive(runSeed, "combat")`, sequential-saved, run-wide (SV 4.3).
- The M1-01 analyzer stays green: no `float`, no signed `/`/`%` outside `IntMath`, sorts only with `[TotalComparer]`, `unchecked` only in the named file.

## Plan-level calls (not fixed by the spec; flagged for review)

1. **The M0 shrine stream** has no row in the SV 4.3 table (boons are an M0 demo). It becomes `Derive(Derive(runSeed, "loot"), "shrine")`, sequential-saved, until real loot replaces shrines (M1-33). M1-05's registry must either register it or remove the shrine.
2. **The M0 `generation` stream is dropped.** M0 never drew from it; `dungeon/…` keys arrive with generation (M1-27).
3. **Saves store `runSeed` and the two counters, not keys.** Keys are re-derived on load, so a hand-edited key cannot exist.
4. **The typed version error covers older saves too.** `SnapshotVersionException` (already carrying `Found`) is thrown for any version ≠ current, with a message per direction; it was "newer only" in M0. Snapshot and command log share `Snapshot.CurrentVersion`, which becomes **2**.
5. **`LabelId` validates its input**: ASCII `[A-Za-z0-9_.:-]` (empty allowed). K-rule 3 says `[a-z0-9_.:-]`, but SV 4.3's own labels (`lootPlan`, `themePerm`, `bossOrder`, `finalOrder`) are mixed case, so uppercase is allowed and the conflict is recorded as open decision **D-12** (Task 4).
6. **Wrapping-file handover:** Task 1 points `DungeonWrappingArithmeticFile` at `Random/KeyAlgebra.cs`; until Task 3 deletes `Pcg32.cs`, that file carries a `#pragma warning disable DUN011` with a "removed by M1-02 Task 3" comment. Task 3 adds an architecture test that Core contains no `DUN` pragma suppressions at all.

## Review Focus

1. **Bad labels:** `LabelId("İ")`, `LabelId("a/b")`, `LabelId("a b")`, `LabelId(null!)` must throw, not hash culture- or encoding-dependent bytes. Test in Task 1.
2. **`Bound(u, 0)` in Release:** must throw `ArgumentOutOfRangeException` in every configuration (an explicit throw, not `Debug.Assert`); `Bound(u, ulong.MaxValue)` must not overflow. Test in Task 1.
3. **Old and out-of-range saves:** a real M0 (version 1) snapshot and command log fail with `SnapshotVersionException { Found = 1 }`; a version-2 save with `runSeed ≥ 2^60` fails with `SnapshotFormatException`; nothing half-loads. Tests in Task 3.
4. **Keyed-sort ties and duplicates:** equal hashes fall back to ordinal id (`"B"` sorts before `"a"`); duplicate ids throw `ArgumentException` (an order over duplicates is not total). Test in Task 2.
5. **Fixed draw count under every seed:** a shrine step advances the shrine counter by exactly 3 and the combat counter by 0, for seeds 0–9 999 and seed 2^60 − 1, and the three options are distinct and in `0..9`. Test in Task 3.
