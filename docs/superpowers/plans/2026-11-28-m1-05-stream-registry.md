# M1-05 Stream Registry and Draw Ledger Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every random stream in Core is a registered row of `content/registry/streams.json`, opened only through a generated handle, with its draw count checked by a `DrawLedger` at the end of each stage run.

**Architecture:**
- **Registry:** a `StreamKind` adds `StreamRow` records to the M1-04 content pipeline. Each row records its path id, parent, label, unsigned indices, count class, count formula, length and cap, stage, retry scope, key type, owner and wave.
- **Handles:** `dotnet run --project src/Sim -- stream-handles` writes `src/Core/Random/StreamHandles.g.cs`, a typed key chain in which every member derives its key with `KeyAlgebra.Derive` using the row's own label and indices. The file is committed, and a test fails if it drifts from `streams.json`.
- **Raw derivation banned:** a new analyzer rule, DUN012, bans `KeyAlgebra.Derive`, `KeyAlgebra.H`, `KeyAlgebra.Absorb` and `DrawStream.Open`, `new DrawStream(...)`, an explicit `default` of `DrawStream` and a `with` on a `DrawStream`, in Core outside the key-algebra file, the handle file, `StreamRegistry.cs` and `KeyedSort.cs`. The final review fixes extend it to a `new`, an explicit `default` or a `with` of a `StreamHandle` or a generated key struct (marked `[StreamKey]`; its constructor is internal and its `Value` get-only, and `StreamHandle`'s likewise), so neither can carry a key the registry never derived. That is what makes "an unregistered path does not compile" true for streams. What it cannot see: a `DrawStream`, `StreamHandle` or key struct that is zero-initialized implicitly (an array element or an unassigned field), and a value drawn with the still-allowed `KeyAlgebra.Draw`/`Mix` from a key computed by hand as plain `ulong` arithmetic; review catches those.
- **Ledger:** a `StageRun` opens fresh ledgered streams (DS15). Its `Close` checks every opened stream against its row's count class and raises `DrawLedgerMismatchException{path, expected, actual}` (a `defect`).
- **Checks:** three V19s checks guard the rows: well-formedness and completeness, `DomainDisjoint`, and the 64-bit collision scan. A V19t test proves `StreamIndependence`.

**Tech Stack:** C# 12 / .NET 8; the M1-02 key algebra (`KeyAlgebra`, `DrawStream`); the M1-04 content loader and validator framework; the M1-01 Roslyn analyzer project (netstandard2.0, Roslyn 4.8); xUnit.

**Spec:** [`docs/roadmap/m1-vertical-slice.md`, M1-05](../../roadmap/m1-vertical-slice.md#m1-05-stream-registry-and-draw-ledger). It implements the following, from SV = `docs/superpowers/specs/2026-11-23-seeds-validation-design.md`:
- **SV 4.2:** streams, the path grammar, count classes, registry handles, and one stage per stream.
- **SV 4.3:** the master stream table: run level, per floor, loot, and the keyed check domains.
- **SV 9.1:** `StreamRow`.
- **SV 4.5:** DS1–DS3, DS7 and DS15.
- **SV 4.1:** K-rule 3 (labels `[A-Za-z0-9_.:-]`) and K-rule 6 (`DomainDisjoint`, the `h:` prefix).
- **SV 5.2 V19:** V19s rows, V19g ledger close (`defect`, `DrawLedgerMismatch`) and V19t `StreamIndependence`.
- **RS 6.4 R-SEED-3, as amended by D-08:** an inert row draws 0. See `docs/superpowers/specs/2026-11-24-m1-scope-rulings-design.md` section 3.

## Global Constraints

- SV 9.1 `StreamRow`, verbatim: `{path (display only), alias[], parent, label (normative), indices[] (normative; each {name, type: ulong|uint|labelId}), class: node|fixed|fixed-per-data|leaf-formula|per-entry|vector|keyed|sequential-saved|display|sim, countFormula, length?, cap?, stage, readers[] (for a vector), consumers[], retryScope: never|floorKey|attempt|stage, rules[], keyType: core|display|sim, owner, source[], wave}`.
- SV 4.2: "Each label together with the indices that follow it is one `Derive` call"; arity is part of the key; "`StreamRow.label` and `indices[]` are normative; the path string is display only"; a `labelId` index enters as `LabelId(id)`; every index is unsigned (SV 4.1).
- SV 4.2 ledger rules per class: `node` counter = 0; `fixed` counter = constant; `fixed-per-data` counter = formula; `leaf-formula` counter = formula on the recorded choice; `vector` every read index < length, no counter; `per-entry` each unit = its count, units ≤ cap; `keyed` no counter; `sequential-saved` saved and restored (not ledgered per stage); `display` not ledgered; `sim` must not derive from `runSeed`.
- DS15: "Every stage run opens fresh stream instances at counter 0, and the DrawLedger closes per stage run … Draw indices are 0-based everywhere."
- K-rule 6: "On any one parent, a stream child and a keyed-hash domain may never share a label (V19s `DomainDisjoint`). New keyed domains are prefixed `h:`."
- V19s (SV 5.2): "label and content-id collision scan (64-bit, across every registered label and manifest id)".
- `DrawLedgerMismatch{path, expected, actual}` is class `defect` (LR5) in every build.
- D-08: "A registered row whose wave is later than the build's wave is inert: the DrawLedger expects 0 draws on it."
- Existing keys must not move: `combat` = `Derive(runSeed, "combat")`, `loot/shrine` = `Derive(Derive(runSeed, "loot"), "shrine")`. `RunStreamsTests` pins seed 7 at `0xb1fbfb392345d2f0` and `0xcd9099bee98dba22`, so saves and state digests are unchanged.
- The determinism analyzer (DUN001–DUN011) stays green, including on generated code. Generated code calls `KeyAlgebra`; it never emits `unchecked`.
- Out of scope:
  - **M1-27:** the GS stages and the real ledger close at GS17.
  - **M1-30:** `hzTagMax` and TL's traps formulas.
  - **M1-28:** Blueprint `GenerationLog` choices.
  - **M1-33:** the other `lootPlan` kinds and the loot block caps.
  - **M2:** the `lineRoll` source rows.
  - **M1-27:** V19s completeness over every `Derive` call site, stages, checks and reports.

## Plan-level calls (mine, flagged for review)

1. **The build wave** is a Core constant, `Wave.Build = Wave.M1`, with the ordering `M1 < M2 < M3 < M4 < Later`. A `StreamRow.wave` holds exactly one of those values. It is not run configuration: M1-06 may move it into the reproducibility key, and that would be its own decision.
2. **Row id = the path with index placeholders**, e.g. `dungeon/floor/{N}/attempt/{a}/layout` or `dungeon/floor/{N}/checks/h:object`. The id is used for lookup and display only; keys come from `label` and `indices`.
   - Grammar: `/`-separated segments, each a label `[A-Za-z0-9_.:-]+` or an index `{name}` (`{name:}` for a `labelId` index), where `name` is `[A-Za-z][A-Za-z0-9]*`.
   - V19s checks that `id == parent + "/" + label + ("/{index}")*` for each declared index; a root row has `parent: null`.
3. **Keyed domains are rows.** A `keyed` row is either a keyed node (`dungeon/floor/{N}/checks`, `dungeon/route`) or a domain under one (`h:object`, `themePerm`, …). Its `indices` name the parts given to `H`. Domain rows carry no count. Handles expose `H` for domains.
4. **Count formulas** use a small grammar: non-negative integer literals; rational literals `p/q`; identifiers; `+`, `*` and parentheses; and `floor(...)`. Evaluation is exact over `Rational`, the result must be a non-negative integer, and parameters are supplied by the stage run.
   - `owed:<OWNER>` marks a formula another owner has not published (TL's traps formulas).
   - Closing a stage that drew on an `owed` row throws `DrawLedgerOwedException` naming the owner. That stage cannot run until the owner supplies the formula, which is the intended hold.
   - `hzTagMax` is not owed: it is a parameter of the terrain formula, and the stage that runs terrain supplies it (M1-30).
5. **`h:steal` is live (wave M1), as SV 4.3 says;** the designs win. Task 6 corrects the roadmap line that calls it "reserved". `h:lurkStealth` is registered with `wave: M2` (inert).
6. **The M0 shrine stream is registered** as `loot/shrine` (class `sequential-saved`, owner MAIN, wave M1, consumer "M0 demo shrine boons"). SV 4.3 gets a footnote saying it lives until M1-33 replaces shrines. `combat` is registered as `sequential-saved` too. `RunStreams` now builds both through handles, with the keys unchanged.
7. **`lineRoll` and the boss-channel block are not registered.** The source kinds (IR) and the boss-channel label (LE) are not named anywhere, so registering them would invent names. They become open decision **D-13** (blocks M1-33). `lineRoll` is inert in M1 anyway, and its reservation stands as a declaration (DS7).
8. **The `lootPlan` kinds:** only `bossCard` (`wave: M2`, inert, per-entry 9 × 4) is registered with the `lootPlan` node now, as the roadmap asks. The live M1 kinds arrive with their consumer in M1-33.
   - The `loot/floor` blocks the roadmap lists are registered as `per-entry` rows: `containers`, `carried`, `dhBlock`, `resistant`, `wandCharges`, `camp`, `vendorPotions`.
   - Counts come from SV 4.3 where it gives them; caps are `owed:LE`.
9. **`ReadByGeneration = true`** for `StreamKind`, so `genContentHash` now covers `streams.json`. The M1-04 test `No_kind_is_read_by_generation_yet` is replaced by one asserting that exactly `registry/streams.json` is read by generation.
10. **DUN012 exempt files** come from the MSBuild property `DungeonKeyDerivationFiles`: semicolon-separated paths relative to the project, matched like the M1-01 wrapping-file property. Core sets it to `Random/KeyAlgebra.cs;Random/KeyedSort.cs;Random/StreamRegistry.cs;Random/StreamHandles.g.cs` (`StreamRegistry.KeyOf` is the reference derivation the handles are tested against, so it calls `KeyAlgebra.Derive` itself).

## Review Focus

1. **Key stability:** a handle's key must equal `StreamRegistry.KeyOf(row, runSeed, indices)` for every row. It must also equal the SV 4.1 vectors where a vector exists: `dungeon`, `dungeon/floor/1`, `attempt/0`, `layout`, `curiosities` (key only; the row is M2), `checks`, and `H(checks, "h:notice", …)`. Tests in Task 3.
2. **Arity and index type:** a `labelId` index is absorbed as `LabelId(value)`, a `uint` is zero-extended, and handles expose no signed parameter. Tests in Task 3.
3. **Inert rows and every count class at close:**
   - `bossCard` drawn once → mismatch;
   - a `node` drawn → mismatch;
   - a `vector` read at index ≥ length → throws at the read;
   - `per-entry` with units > cap, or a unit's count ≠ formula → mismatch;
   - a stream opened twice in one run → throws;
   - closing twice → throws;
   - a draw after close → throws.

   Tests in Task 5.
4. **Formula edge cases:** `floor(3/10*7)` = 2; a missing parameter; a negative or non-integer result; `owed:TL`; whitespace; `2*(3+4)`. Tests in Task 1.
5. **DUN012 bypasses:** a method group `Func<ulong,string,ulong[],ulong> f = KeyAlgebra.Derive`, a `using static Dungeon.Core.KeyAlgebra` call, and `DrawStream.Open` through an alias are all reported. The exempt files are clean with either path separator. Tests in Task 4.
